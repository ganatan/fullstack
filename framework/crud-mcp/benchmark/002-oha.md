# Benchmark Rust Release vs Rust Debug vs Python avec oha

`oha` est un outil de benchmark HTTP écrit en Rust.

Il permet d'envoyer un grand nombre de requêtes concurrentes vers une API et de mesurer notamment :

```text
nombre total de requêtes
requêtes par seconde
temps moyen de réponse
temps minimum
temps maximum
percentiles
codes HTTP
taux de réussite
```

Endpoint testé :

```text
GET http://localhost:3000/persons
```

L'objectif est de comparer trois exécutions avec exactement le même scénario :

```text
Rust Release
Rust Debug
Python
```

---

## 1. Installer oha

Installation avec Cargo :

```bash
cargo install oha
```

Sous Windows, il est également possible d'utiliser :

```powershell
winget install hatoo.oha
```

---

## 2. Vérifier l'installation

```bash
oha --version
```

Afficher les options disponibles :

```bash
oha --help
```

---

## 3. Vérifier l'API

Avant chaque benchmark, démarrer le backend concerné puis vérifier :

```text
http://localhost:3000/persons
```

La réponse doit être retournée correctement.

---

## 4. Conditions du benchmark

Les trois tests utilisent exactement les mêmes paramètres.

```text
Endpoint      : GET /persons
Host          : localhost
Port          : 3000

Connections   : 100
Duration      : 60 secondes
Rate limit    : aucune
KeepAlive     : activé
Wait ongoing  : activé
```

Commande de référence :

```powershell
oha -c 100 -z 60s -w http://localhost:3000/persons
```

---

## 5. Signification des paramètres

### Connexions concurrentes

```text
-c 100
```

Utilise :

```text
100 connexions concurrentes
```

Plusieurs requêtes peuvent donc être exécutées simultanément.

---

### Durée

```text
-z 60s
```

Le benchmark envoie des requêtes pendant :

```text
60 secondes
```

---

### Attendre les dernières requêtes

```text
-w
```

Lorsque les 60 secondes sont terminées, `oha` laisse les requêtes déjà en cours se terminer proprement.

---

## 6. Principe du benchmark

Le fonctionnement est :

```text
100 connexions concurrentes
        ↓
GET /persons
        ↓
réponse
        ↓
nouvelle requête immédiatement
        ↓
GET /persons
        ↓
...
        ↓
pendant 60 secondes
```

Aucune pause volontaire n'est ajoutée entre les requêtes.

L'objectif est de mesurer la capacité de chaque backend sous une charge continue.

---

## 7. KeepAlive

Le KeepAlive reste activé.

Les connexions HTTP peuvent donc être réutilisées entre plusieurs requêtes.

Ne pas utiliser :

```text
--disable-keepalive
```

---

## 8. Ne pas limiter le débit

Ne pas utiliser :

```text
-q
```

Aucune limite de requêtes par seconde ne doit être imposée.

Chaque backend répond donc aussi rapidement qu'il le peut.

```text
requête
    ↓
réponse
    ↓
nouvelle requête
    ↓
réponse
    ↓
...
```

---

## 9. Visualisation pendant le benchmark

`oha` affiche directement l'évolution du benchmark dans le terminal.

Commande :

```powershell
oha -c 100 -z 60s -w http://localhost:3000/persons
```

Pendant les 60 secondes, la visualisation permet de suivre le test en temps réel.

---

## 10. Enregistrer le résultat

Le paramètre :

```text
-o
```

permet d'enregistrer le résultat dans un fichier.

Le format utilisé sera :

```text
JSON
```

avec :

```text
--output-format json
```

Exemple :

```powershell
oha -c 100 -z 60s -w --output-format json -o "result.json" http://localhost:3000/persons
```

Cette commande permet donc d'avoir :

```text
visualisation dans le terminal
+
résultat enregistré dans un fichier JSON
```

---

## 11. Structure des résultats

Créer un dossier :

```text
benchmarks/
└── oha/
```

Les trois résultats seront enregistrés séparément :

```text
benchmarks/
└── oha/
    ├── rust-release.json
    ├── rust-debug.json
    └── python.json
```

Si le terminal est déjà positionné dans :

```text
benchmarks\oha
```

les noms de fichiers peuvent directement être utilisés :

```text
rust-release.json
rust-debug.json
python.json
```

## 12. Warm-up

Avant chaque mesure officielle, effectuer un test de chauffe de :

```text
30 secondes
```

Commande :

```powershell
oha -c 100 -z 30s -w http://localhost:3000/persons
```

Le résultat du warm-up n'est pas conservé.

Le but est simplement de préparer :

```text
backend
pool PostgreSQL
connexions HTTP
KeepAlive
```

```bash

```

Puis lancer directement l'exécutable.

```powershell
.\target\release\rust-starter.exe
```

```powershell

```

Puis lancer le benchmark officiel :

```powershell
oha -c 100 -z 60s -w --output-format json -o "rust-release.json" http://localhost:3000/persons
```

Résultat :

```text
rust-release.json
```

# 14. Test 2 — Rust Debug

Arrêter le backend Rust Release.

Lancer ensuite Rust avec :

```bash

```

Effectuer éventuellement le warm-up :

```powershell

```

Puis lancer exactement le même benchmark :

```powershell
oha -c 100 -z 60s -w --output-format json -o "rust-debug.json" http://localhost:3000/persons
```

Résultat :

```text
rust-debug.json
```

## 18. Requests/sec

```text
Requests/sec
```

correspond au nombre de requêtes traitées chaque seconde.

Exemple :

```text
12 000 requests/sec
```

Pour cette mesure :

```text
plus élevé = meilleur
```

C'est l'un des principaux indicateurs du benchmark.

---

## 19. Average

```text
Average
```

correspond au temps moyen nécessaire pour traiter une requête.

Exemple :

```text
8 ms
```

Pour cette mesure :

```text
plus bas = meilleur
```

---

## 20. Fastest

```text
Fastest
```

correspond à la requête ayant obtenu la réponse la plus rapide.

```text
plus bas = meilleur
```

---

## 21. Slowest

```text
Slowest
```

correspond à la requête ayant obtenu la réponse la plus lente.

```text
plus bas = meilleur
```

---

## 22. Response time distribution

`oha` fournit également la distribution des temps de réponse.

Par exemple :

```text
50 %
90 %
95 %
99 %
```

Le percentile :

```text
95 %
```

signifie que 95 % des requêtes ont répondu dans un temps inférieur ou égal à cette valeur.

Ces valeurs permettent de voir si certaines requêtes deviennent beaucoup plus lentes sous charge.
